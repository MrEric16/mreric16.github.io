  /* Grid floor: a large rectangle tilted back via perspective, converging toward the
     horizon where the sun sits - rebuilt properly after the first pass (thin, faint
     lines plus a separate barely-visible rays layer) turned out not to read at all
     against the reference Mr Eric sent. This version matches that reference directly:
     bold glowing lines (a wide soft "bloom" layer underneath a thin bright core layer,
     in both directions - the standard way to fake a neon glow in pure CSS without an
     actual blur filter, which would soften the whole grid rather than just the line
     edges), and a continuous hue-rotate sweeping the full colour wheel so the lines
     genuinely cycle colour rather than sitting on one fixed hue. The rays layer from
     round 2 is gone entirely rather than kept alongside this - it wasn't what "the
     lines" meant and was visually redundant with a grid this bold anyway.
     Round 4: height bumped 45vh -> 140vh after Mr Eric reported the grid rendering as
     a thin sliver way down at the very bottom, nowhere near the sun. Real cause:
     rotateX(65deg) dramatically foreshortens an element's apparent on-screen height -
     tipping a rectangle back that steeply compresses most of its height into a sliver
     regardless of the raw height value, so 45vh of pre-rotation rectangle was never
     going to read as tall once actually tilted. Overshooting the raw height
     substantially compensates for that compression so the visible (post-rotation)
     grid actually reaches up toward the sun rather than hugging the very bottom edge. */
  /* Round 5: two more fixes from Mr Eric's screenshots.
     (a) Centre lines rendering visibly brighter than the sides on desktop - this is a
     rendering artifact of the perspective transform itself, not a colour/opacity bug:
     rotateX compresses the repeating pattern non-uniformly, so near the vanishing
     point (dead centre) many more repetitions of the 44px grid get packed into the
     same on-screen space than at the edges, and those compressed/overlapping lines
     anti-alias into a visibly brighter, denser-looking band. Widened the repeat
     interval 44px->70px (fewer total repetitions competing for the same compressed
     space near centre reduces how much pile-up there is) and took the glow layer's
     opacity down slightly (.35->.22) since it's the layer that compounds most
     visibly when lines overlap.
     (b) Height still wasn't reaching the sun at 140vh - going substantially further
     (400vh) this time rather than nudging it again, since the exact foreshortening
     ratio clearly needs a bigger margin than estimated last round. */
  body.usertheme-synthwave:not(.dark-mode)::after{
    content:'';
    position:fixed; z-index:-1; pointer-events:none;
    left:0; right:0; bottom:0;
    height:400vh;
    transform-origin:bottom;
    transform:perspective(300px) rotateX(65deg);
    background-image:
      repeating-linear-gradient(90deg, rgba(255,20,200,.22) 0px, rgba(255,20,200,.22) 9px, transparent 9px, transparent 70px),
      repeating-linear-gradient(90deg, rgba(255,170,235,1) 0px, rgba(255,170,235,1) 2px, transparent 2px, transparent 70px),
      repeating-linear-gradient(0deg, rgba(255,20,200,.22) 0px, rgba(255,20,200,.22) 9px, transparent 9px, transparent 70px),
      repeating-linear-gradient(0deg, rgba(255,170,235,1) 0px, rgba(255,170,235,1) 2px, transparent 2px, transparent 70px);
    animation:synthwaveGridFlow 6s linear infinite;
    /* Round 6: one horizontal line was still rendering as a single sharp white-hot
       band, clearly brighter than everything else - a more extreme version of the
       same root cause as round 5 (rotateX compression), not a new bug. At the very
       far edge of a 400vh-tall rotated rectangle, the repeating pattern compresses so
       hard that dozens of repetitions collapse into one row of screen pixels right
       near the vanishing point, and that pile-up anti-aliases into a single
       over-bright line rather than a uniformly brighter zone. Making the grid taller
       last round to reach the sun made this specific artifact worse, not better -
       taller means the far edge sits even further into extreme-compression territory.
       Rather than fight the aliasing directly again, masking the worst zone out
       entirely: fade the grid to transparent well before it reaches that point. This
       is also just correct for the reference look anyway - a real synthwave grid
       fades toward the horizon rather than staying full-brightness all the way up. */
    mask-image:linear-gradient(to top, black 0%, black 45%, transparent 78%);
    -webkit-mask-image:linear-gradient(to top, black 0%, black 45%, transparent 78%);
  }
  @keyframes synthwaveGridFlow{
    0%{ filter:hue-rotate(0deg); }
    100%{ filter:hue-rotate(360deg); }
  }
